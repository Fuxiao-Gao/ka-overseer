16. Supersedes rule 15. The bot's PR-description finding opens ONE review thread (first comment starts <!-- kube-agents-bot:description -->); resolving that thread does NOT answer it, only editing the PR body does. While the body still owes an answer, every later review repeats the finding in its SUMMARY BODY under 'The pull request description is still unanswered.' and keeps the AI Review check neutral, so zero unresolved threads does not mean clear: read the latest kube-agents-bot review body. It is not an issue comment, so top-level comments will not show it. Editing the body triggers no review; a plain /review on an unchanged commit is a re-cut that only checks for missing or empty sections and can go green on a body that is still wrong (#2226). After a body edit, comment /review fresh and read a review newer than the edit before calling the PR clear. Evidence: #2265.

- (added 2026-10-05) No session approves, requests changes, `/lgtm` or `/approve` on any PR; reviews a human asks for go in as comments. When a review is done and the session would have lgtm'd, it reports `waiting-human: lgtm wanted on #N`; the human does the once-over and posts it. This supersedes any "never lgtm the human's own PRs" rule, which is now the general case.
